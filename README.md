# 창릉 S-4 입주예정자협의회 홈페이지

고양창릉 S-4블록(LH 공공분양, 1,024세대) 입예협 홈페이지입니다.

- **안내 페이지** (공지, 일정, 단지 · 평면, 계산기, 사전점검 등): `assets/data.js`에서 내용 관리
- **회원 기능** (가입 · 승인, 위임동의서, 현황판 자동 반영, 게시판, 투표, 민원): Supabase(무료 DB · 인증 · 파일 저장) 연결

서버를 연결하기 전에도 사이트는 열립니다. 회원 기능 자리에는 "준비 중" 안내가 나옵니다.

---

## 1. 어떻게 동작하나요

1. 입주예정자가 **동 · 호수를 고르고 비밀번호**만 정해 가입합니다. **동 · 호수가 곧 아이디**입니다. 가입할 때 **당첨 조회 화면 캡처나 계약서 첫 장 사진**을 올립니다.
   로그인도 동 · 호수 선택 + 비밀번호입니다.
2. 운영진이 **운영진 페이지 → 가입 승인**에서 사진을 보고 승인하거나 반려합니다. 처리하는 즉시 사진은 삭제됩니다.
3. **공급계약(2026-11-16~) 후** 회원이 **위임동의서**(계약자 성명 + 서명)를 내면 **위임동의 현황판에 바로 반영**됩니다. 시작 시각은 DB `app_settings`의 `consent_open_at` 값입니다.
4. 이용 범위: **가입 회원** = 게시판 읽기 · 쓰기 · 댓글, 투표 결과 보기 / **위임 회원** = + 투표 · 단체민원 참여, 세대별 위임 현황. 운영진은 위임 회원과 같습니다.
5. 게시판 · 투표 · 민원 참여도 로그인한 계정으로 처리됩니다. 작성자는 "403동 입주예정자"로 자동 표시되고, 원하면 내 정보에서 닉네임을 정해 "닉네임 · 403동"으로 바꿀 수 있습니다. 호수는 표시하지 않습니다.

### 입주자가 아닌 사람 · 중복 가입을 막는 장치

| 장치 | 내용 |
|---|---|
| 계약서 확인 승인 | 운영진이 계약서를 보고 승인해야 위임동의 · 게시판 · 투표를 쓸 수 있습니다 |
| 1세대 1계정 | 아이디가 동 · 호수라서 한 세대에는 계정이 **하나만** 만들어집니다. 회원 정보도 로그인한 세대로만 만들 수 있습니다(DB 제약 · 트리거) |
| 사칭 대응 | 남이 먼저 우리 세대로 가입 신청을 했다면, 실제 계약자가 운영진에게 연락 → 운영진이 그 계정을 **계정 삭제** → 세대가 풀려 실제 계약자가 가입 |
| 1세대 1표 | 위임동의서, 투표, 민원 참여는 세대당 한 번만 됩니다(DB 기본키) |
| 서버가 세대를 채움 | 동의서 · 투표의 세대, 글 작성자는 화면에서 보낸 값이 아니라 로그인 계정에서 서버가 채웁니다 |

이 규칙들은 모두 데이터베이스의 행 단위 보안 정책(RLS)과 트리거로 강제됩니다. 화면 코드를 조작하거나 API를 직접 호출해도 넘을 수 없습니다.

## 2. 처음 설정하기 (약 30분)

### ① Supabase 프로젝트 만들기
1. supabase.com 가입 → **New project**
2. Region은 **Northeast Asia (Seoul)**, DB 비밀번호는 안전한 곳에 보관

### ② 로그인 설정
**Authentication → Sign In / Providers → Email**
- **Enable Email provider**: 켬
- **Confirm email**: **끔** (아이디 방식이라 메일을 보내지 않습니다)
- **Minimum password length**: 8

**Authentication → URL Configuration → Site URL**: 사이트 주소(예: `https://창릉s4.kr`)

### ③ 데이터베이스 만들기
**SQL Editor → New query**에 아래 파일을 차례로 붙여 넣고 **Run**:
1. `supabase/schema.sql` — 테이블, 보안 정책, 계약서 저장소
2. `supabase/units_seed.sql` — 1,028세대 동 · 호수
3. `supabase/storage_limits.sql` — 계약서 5MB · 사진/PDF 제한

여러 번 실행해도 안전하게 만들어져 있습니다(이미 있는 것은 건너뜀).

### ④ 사이트에 연결
**Project Settings → API**에서 **Project URL**과 **anon public** 키를 복사해 `assets/config.js`에 넣습니다.

```js
window.S4_CONFIG = {
  supabaseUrl: "https://abcdefgh.supabase.co",
  supabaseAnonKey: "eyJhbGciOi...",
  idDomain: "id.yourdomain.kr"
};
```

- anon 키는 공개되어도 되는 키입니다. 권한은 DB 정책이 막습니다.
- **service_role 키는 절대 넣지 마세요.** 모든 보안 정책을 무시하는 키입니다.
- `idDomain`: 동 · 호수를 내부적으로 `403-1803@idDomain` 같은 이메일 형식으로 바꿔 저장합니다. 실제로 메일을 보내지는 않습니다. **한 번 정하면 바꾸지 마세요**(바꾸면 기존 회원이 로그인할 수 없습니다). 협의회 도메인을 샀다면 그 하위 주소(예: `id.창릉s4.kr`의 영문 표기)를 쓰세요. 가입할 때 "Email address is invalid" 오류가 나면, 그 도메인에 MX 레코드를 하나 추가하면 해결됩니다.

### ⑤ 첫 운영진 지정
1. 사이트에서 운영진이 될 사람이 자기 세대로 일반 회원처럼 가입합니다.
2. SQL Editor에서 실행합니다(그 사람의 동-호):
   ```sql
   update public.profiles set status = 'approved', is_admin = true where unit_id = '401-101';
   ```
3. 이후에는 SQL이 필요 없습니다. 다른 운영진은 운영진 페이지 → 회원에서 **운영진 지정** 버튼으로 임명합니다(승인된 회원만 가능).

### ⑥ 사이트 올리기
이 폴더 전체를 아래 중 한 곳에 올립니다.
- **Netlify Drop**: app.netlify.com/drop 에 폴더를 끌어다 놓기
- **Cloudflare Pages**: Workers & Pages → Pages → 파일 직접 업로드, 또는 ⑧의 GitHub 저장소 연결(추천: 올리면 자동 갱신)
- **GitHub Pages**: 저장소 Settings → Pages

`_headers` 파일(다른 사이트가 이 사이트를 틀 안에 넣지 못하게 하는 설정 등)은 Netlify · Cloudflare Pages에서 자동 적용됩니다.

도메인은 가비아 · 후이즈 등에서 사서 호스팅 서비스의 Custom domain 메뉴에 연결합니다. HTTPS는 자동입니다.

### ⑦ 소식 자동 수집 켜기 (선택, 약 10분)
매일 아침 7시 13분에 구글 뉴스의 "창릉" 관련 기사와 LH 청약플러스의 고양창릉 공고를 가져와 **언론보도 · 공지사항 · 주요일정 · 홈 "새 소식"**에 올립니다. 기사는 제목 · 출처 · 날짜 · 링크만 가져오고, 본문은 저작권 때문에 가져오지 않습니다.

LH 공고는 공공데이터포털 API 세 가지를 씁니다.
- **분양임대공고문 조회**: 공고명 · 상태 · 게시일 · 마감일 · 링크
- **공고별 상세정보 조회**: 공급 일정, 단지 정보, 계약 장소, 첨부파일(공고문 PDF 등)
- **공고별 공급정보 조회**: 주택형별 금회 공급 · 총 세대수

공지사항의 LH 공고마다 **"공고 상세 보기"**가 생기고, S-4 공고의 공급 일정은 **주요일정** 맨 위에 "LH 공식 일정"으로 나옵니다. LH 공고는 매일 다시 확인해 상태 · 일정이 바뀌면 갱신합니다.

1. **LH 공고 인증키(무료)**: 공공데이터포털(data.go.kr) 가입 → 아래 세 서비스를 각각 검색해 **활용신청**(자동 승인) → 마이페이지에서 일반 인증키 복사(세 서비스가 같은 키를 씁니다). 키가 없으면 뉴스만 수집합니다.
   - 한국토지주택공사_분양임대공고문 조회 서비스
   - 한국토지주택공사_분양임대공고별 상세정보 조회 서비스
   - 한국토지주택공사_분양임대공고별 공급정보 조회 서비스
2. **수집기 올리기**: Supabase 대시보드 → **Edge Functions → Deploy a new function → Via Editor** → 이름 `collect-news` → `supabase/functions/collect-news/index.ts` 내용을 붙여 넣고 Deploy.
   함수 설정에서 **Verify JWT를 끕니다**(호출 권한은 함수 안에서 직접 확인합니다).
3. **Secrets 등록**: Edge Functions → Secrets
   - `CRON_SECRET`: 아무 긴 문자열(예: 비밀번호 생성기로 만든 32자)
   - `LH_API_KEY`: 1번에서 받은 인증키
4. **매일 실행 예약**: `supabase/cron.sql`의 `<PROJECT_REF>`, `<CRON_SECRET>`을 바꿔 SQL Editor에서 실행.
5. 확인: 운영진 페이지 → **자동 수집** → **지금 수집**. "찾은 소식 N건"이 나오면 끝입니다.

### ⑧ LH 공고문(PDF) 자동 읽기 켜기 (선택, 약 10분)
S-4 관련 LH 공고에 첨부된 **공고문 PDF를 매일 읽어** 일정과 주요 정보를 뽑습니다.
- **일정**: 유상옵션(선택품목) 선택, 동호 배정, 서류 제출, 계약 체결, 사전점검, 입주지정기간, 중도금 · 잔금 등 → **주요일정 · 홈 "다가오는 일정"에 날짜가 자동 반영**되고 "자동" 표시가 붙습니다. 같은 일정의 "날짜 미정" 항목은 자동으로 대체됩니다.
- **주요 정보**: 전매제한, 거주의무, 계약금 · 중도금 · 잔금, 중도금 대출, 발코니 확장 등 → **공지사항의 해당 LH 공고에 "공고문 자동 요약"**으로 표시. 일정마다 근거가 된 공고문 원문 한 줄을 함께 보여줘 바로 확인할 수 있습니다.
- 자격 기준일(공고일 현재 · 출생일 등)은 일정으로 잡지 않습니다. 같은 공고문은 다시 읽지 않고, 새 공고문이 붙으면 다시 읽습니다.

PDF 읽기는 Supabase에서 돌리기에 무거워(실행당 CPU 2초 제한) **GitHub Actions**(무료)에서 매일 07:37에 실행합니다.
1. github.com에서 협의회 계정으로 **새 저장소(Public)**를 만들고 이 폴더 전체를 올립니다(`.github` 폴더 포함).
2. 저장소 **Settings → Secrets and variables → Actions → New repository secret**에 두 개 등록
   - `SUPABASE_URL`: 프로젝트 주소
   - `SUPABASE_SERVICE_ROLE_KEY`: Supabase → Project Settings → API의 **service_role** 키 (이 키는 여기에만 넣고, 사이트 파일에는 절대 넣지 마세요)
3. **Actions** 탭 → "LH 공고문 읽기" → **Run workflow**로 한 번 실행해 확인합니다.

같은 저장소를 사이트 호스팅에도 쓰면 편합니다(⑥의 Cloudflare Pages에서 이 저장소를 연결하면, 파일을 고쳐 올릴 때마다 사이트가 자동으로 갱신됩니다).

엉뚱한 기사가 걸리면 운영진 페이지 → 자동 수집에서 **숨기기**를 누르면 사이트에서 빠집니다. 수집된 기사의 제목은 운영진도 고칠 수 없습니다(원문 그대로).

### ⑨ 테스트 후 정식 오픈 (데이터 초기화)
입예협 분들과 실제 서버에서 시험해 본 뒤, 정식 오픈 직전에 한 번 실행합니다.
1. SQL Editor에서 `supabase/reset.sql` 실행 → 마지막 확인 결과가 모두 0이고 세대만 남아 있으면 됩니다.
2. **Storage → contracts**에 남은 파일이 있으면 모두 선택해 삭제합니다(계약서 사진은 SQL로 지울 수 없습니다).
3. 운영진이 자기 세대로 다시 가입 → ⑤의 SQL로 운영진 지정.
4. 운영진 페이지 → 자동 수집 → **지금 수집**, GitHub Actions → **Run workflow**로 소식과 공고문 일정을 다시 채웁니다.
5. `assets/data.js`의 예정 공지 · 알림 띠를 오픈에 맞게 고칩니다.

## 3. 운영하기

| 할 일 | 어디서 |
|---|---|
| 가입 승인 | 운영진 페이지 → 가입 승인 → **승인** |
| 사진이 흐린 경우 | **반려 · 다시 내기** (사유 필수). 회원이 계약서만 다시 올리면 됩니다 |
| 다른 세대 계약서 · 사칭 | **계정 삭제**. 세대가 풀려 실제 계약자가 가입할 수 있습니다 |
| 가입하다 멈춘 계정 | 운영진 페이지 → 회원 → 가입 중단 계정 → 계정 삭제 |
| 위임동의 명단 · CSV | 운영진 페이지 → 위임동의 명단 |
| 잘못 승인한 계정 취소 | 운영진 페이지 → 회원 → 승인 취소 (그 세대의 위임동의도 함께 삭제) |
| 운영진 지정 · 해제 | 운영진 페이지 → 회원 → 승인된 회원 줄의 **운영진 지정** / **운영진 해제** |
| 투표 · 민원 열기 | 운영진 페이지 → 투표 / 민원 |
| 자동 수집 기사 숨기기 · 즉시 수집 | 운영진 페이지 → 자동 수집 |
| 공지 · 일정 · 공정률 · 사진 | `assets/data.js` 수정 후 다시 올리기 |

**"이미 가입되어 있습니다"라며 가입이 안 된다는 연락을 받으면**: 그 세대 계정을 운영진 페이지에서 확인합니다. 본인이 예전에 가입한 것이면 비밀번호 문제이고, 모르는 가입이면 사칭이므로 **계정 삭제** 후 다시 가입하게 안내합니다.

**비밀번호를 잊은 회원**: 이메일이 없는 방식이라 재설정 메일을 보낼 수 없습니다. 본인 확인(계약서 등) 후 운영진 페이지 → 회원에서 그 세대를 **계정 삭제**하면 같은 세대로 다시 가입할 수 있습니다. 위임동의는 다시 제출해야 합니다. 계약서 파일까지 함께 지워지므로 Supabase 대시보드보다 운영진 페이지에서 삭제하세요.

**무료 요금제 주의**: Supabase 무료 프로젝트는 일정 기간 사용이 없으면 일시 정지될 수 있습니다. 정지되면 대시보드에서 다시 켜면 되고, 데이터는 남아 있습니다. 위임동의 명단은 주기적으로 CSV로 받아 보관하세요.

### `assets/data.js`에서 고치는 내용

## 4. 보안 메모

- 모든 테이블에 RLS를 켰고, 필요한 권한만 `grant`했습니다.
- 회원 정보 보호 트리거: 가입할 때 승인 상태나 운영자 권한을 넣어도 무시됩니다. 로그인한 세대와 다른 세대로는 회원 정보를 만들 수 없고, 세대(아이디)는 운영진도 바꿀 수 없습니다.
- 계정 삭제는 운영진만, 운영진 계정은 SQL Editor에서만 지울 수 있습니다.
- 위임동의서는 제출 후 수정할 수 없고(철회 후 재제출만 가능), 제출 · 철회 기록이 남습니다.
- 계약서는 비공개 저장소에 `회원ID/` 폴더로만 올릴 수 있고, 본인과 운영진만 열 수 있으며, 처리 즉시 삭제합니다.
- 모든 페이지에 Content-Security-Policy를 걸어, 이 사이트 파일 · Google Fonts · Supabase 외의 스크립트나 연결은 막힙니다.
- 화면에 표시되는 모든 값은 HTML로 해석되지 않게 처리합니다.

제작 과정에서 실제 Supabase 구성요소(Postgres 17, PostgREST, Supabase Auth)를 로컬에 띄워 검증했습니다.
- **보안 검사 87개**: 셀프 승인, 운영자 권한 탈취, 남의 계약서 열람 · 업로드, 같은 세대 두 번째 계정, 다른 세대로 회원 정보 만들기, 동의서 세대 위조, 작성자 위조, 재투표, 마감 투표, 일반 회원의 계정 삭제, 비회원 열람 등

## 5. 위임동의서 양식

`위임동의서` 페이지의 문구(위임 범위, 위임하지 않는 사항, 기간 · 철회, 개인정보, 제3자 제공)는 **초안**입니다. 협의회 회의에서 검토하고, 필요하면 법률 자문을 받은 뒤 확정하세요. 문구를 바꾸면 `assets/api.js`의 `FORM_VERSION`도 올려주세요. 제출 기록에 양식 버전이 함께 남습니다.
